# Лабораторная работа 4 — оконные функции и аналитика данных

## Цель и результат

Показать ранжирование строк внутри категорий, расчёт нарастающего итога, долей и изменений выручки без потери детальных строк. Решение написано для PostgreSQL и использует уже созданную в лабораторной 1 схему маркетплейса.

## Состав папки

- `00_schema_from_lab01.sql` — самостоятельная копия схемы из `lab01/01_schema.sql`.
- `01_seed_data_from_lab02.sql` — самостоятельная копия тестовых данных из `lab02/01_seed_data.sql`, дополненная датами заказов за 30 дней и парой товаров с одинаковой ценой для наглядного сравнения рангов.
- `02_window_analytics.sql` — все обязательные аналитические запросы.
- `03_window_vs_group_by.sql` — две реализации одной задачи для сравнения оконной функции и `GROUP BY`.
- `report.md` — краткий отчёт с ходом работы и выводом.

## Как запускать

Создайте отдельную учебную базу `marketplace_lab04`, чтобы не затронуть свои данные. Скрипт схемы удаляет и пересоздаёт схему `marketplace` только внутри этой учебной базы.

Выполните файлы по порядку: сначала `00_schema_from_lab01.sql`, затем `01_seed_data_from_lab02.sql`, после этого `02_window_analytics.sql` и `03_window_vs_group_by.sql`. Для `psql` из корня репозитория:

```text
createdb -U postgres marketplace_lab04
psql -U postgres -d marketplace_lab04 -v ON_ERROR_STOP=1 -f lab04/00_schema_from_lab01.sql
psql -U postgres -d marketplace_lab04 -v ON_ERROR_STOP=1 -f lab04/01_seed_data_from_lab02.sql
psql -U postgres -d marketplace_lab04 -v ON_ERROR_STOP=1 -f lab04/02_window_analytics.sql
psql -U postgres -d marketplace_lab04 -v ON_ERROR_STOP=1 -f lab04/03_window_vs_group_by.sql
```

Графики и диаграммы методичкой не предусмотрены: результат лабораторной — таблицы, возвращаемые SQL-запросами.

## Выполнение технического задания

1. Первый запрос выводит `ROW_NUMBER`, `RANK` и `DENSE_RANK` для товаров в каждой категории. В тестовых данных товары 1 и 13 специально имеют одинаковую максимальную цену в одной категории: `ROW_NUMBER` выдаёт разные последовательные номера, `RANK` присваивает одинаковый ранг и пропускает следующий номер, а `DENSE_RANK` присваивает одинаковый ранг без пропуска.
2. CTE `ranked_products` нумерует товары в каждой категории, а внешний запрос оставляет первые три строки.
3. CTE `daily_revenue` сначала считает выручку каждого дня. Оконный `SUM` затем добавляет нарастающий итог, не объединяя дневные строки.
4. Сначала вычисляется выручка продавца в категории; `SUM(revenue) OVER (PARTITION BY category_id)` даёт сумму всей категории, после чего рассчитывается процентная доля продавца.
5. `LAG` получает выручку прошлого дня, `LEAD` — следующего. Разности показывают изменение относительно соседних дней.
6. В `03_window_vs_group_by.sql` доля продавца вычислена и оконной суммой, и отдельной группировкой с соединением итогов категории. Оконный вариант короче и оставляет строки продавцов вместе с итогом раздела в одном наборе.

## Контрольные вопросы

1. **Что такое оконная функция и чем отличается от `GROUP BY`?** Она считает по связанным строкам и сохраняет каждую исходную строку; `GROUP BY` сворачивает строки в группы.
2. **За что отвечает `OVER`?** Задаёт окно, по которому функция выполняет расчёт.
3. **Что задаёт `PARTITION BY` и чем похожа/непохожа на `GROUP BY`?** Делит строки на независимые группы для вычисления; как `GROUP BY`, группирует логически, но не схлопывает строки.
4. **Для чего `ORDER BY` внутри `OVER`?** Задаёт порядок строк для рангов, смещений и накопительных расчётов.
5. **Чем различаются `ROW_NUMBER`, `RANK`, `DENSE_RANK` при равенстве?** `ROW_NUMBER` всегда различается; `RANK` даёт одинаковый ранг с пропусками; `DENSE_RANK` — одинаковый ранг без пропусков.
6. **Как выбрать N лучших строк в каждой группе?** Пронумеровать `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)` в CTE и отфильтровать номер `<= N`.
7. **Как агрегат становится оконным?** К агрегату добавляют `OVER`; например `SUM(x) OVER (...)` показывает сумму окна рядом с каждой строкой.
8. **Что такое нарастающий итог?** Сумма от начала упорядоченного набора до текущей строки; считается `SUM(x) OVER (ORDER BY ... ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)`.
9. **Что делают `LAG` и `LEAD`?** Возвращают значение предыдущей и следующей строки окна; ими сравнивают соседние дни или периоды.
10. **Когда окно удобнее обычной группировки?** Когда нужны одновременно детальные строки и показатели их группы, например выручка продавца и его доля в категории.
